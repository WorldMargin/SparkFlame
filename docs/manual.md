# 星火燎原 · 使用文档

抖音自动续火花（LSPosed 模块）。一句话：**给「抖音判定今天还没互动」的会话自动发一条你自己写的私信**，每天每个会话最多一条。

> 目录：一、安装与开启　二、界面　三、什么时候会发　四、模板与变量　五、宏与函数　
> 六、脚本 API　七、编辑器　八、用 AI 写脚本　九、常见问题　十、数据与文件位置

---

## 一、安装与开启

1. 安装 APK，在 **LSPosed** 里勾选模块、作用域选「抖音」，然后**重启抖音**。
2. 打开模块界面：
   - 桌面图标「星火燎原」；
   - 或 **抖音 → 我 → 设置 → 续火花**，会弹两个选项：
     - **立即续火花（就地发送）**：不跳出抖音，直接给「已选目标」发一轮，结果用提示告诉你；
     - **跳转 APP（打开管理界面）**：打开模块界面。跨应用跳转时抖音还会弹一次「是否跳转」，**3 秒内点「继续」**才进得去。
3. 到 **设置** 页打开 **总开关**（默认关闭），打开后才会自动发送。
4. 到 **设置** 页点一次 **刷新会话**，让抖音把会话列表、头像、火花天数写进模块。

> **抖音没在运行时会怎样**：模块和抖音是两个进程，续火花、刷新会话都要抖音进程来执行。
> 界面在发送 / 刷新前会先探活：抖音不在就不下指令，而是提示你 **先打开抖音**（可以直接点「打开抖音」），
> 打开并等它就绪后会自动把刚才那件事做完。

## 二、界面

底部五个标签：**续火花 / 模板 / 标签 / 宏/函数 / 设置**。续火花与模板页用**可折叠分组卡片**（点标题折叠 / 展开）；标签、宏/函数页是卡片列表（每条一张卡片）。

### 2.1 续火花

- 顶部内分 **「已选目标」/「未选目标」** 两页，每页再按 **单聊 / 群聊** 分成两张卡片。
- 顶部有**搜索框**，按昵称 / 备注过滤，整组都不匹配时卡片自动收起。
- 搜索框下面还有 **「标签 / 来源」两排筛选**（标签可多选、来源单选），详见 2.3。
- **「已选目标」页**是需要续的会话（待发 / 待对方回复 / 待重燃）；**「未选目标」页**是其余的
  （今日已续、没有火花、手动移出的）。
- 勾选框 + 底部按钮可以**批量移动**：`＋` 移入已选目标，`－` 移出。
- **点会话行**进入单会话文案编辑；**长按整行**也可以多选。
- 会话行右侧的「手动移入 / 手动移出」标记，表示它的归属是手动定死的，不受抖音判定影响。
- 「发送全部 N 个 / 发送给选中的 N 个」按钮：**勾选了就发勾选的，没勾就发「已选目标」全部**（见第三节）。

页面底部还有一张 **「被隐藏」折叠卡片**：连续多次没在抖音出现的会话会收在这里，详见 4.3。

**新手引导**：右下角有一个「引导」小胶囊，**浮在界面之上、不占页面布局**，可以**拖动**到不碍事的位置；点开是浮层清单，右上角「最小化」收起。清单分 **基础 / 进阶** 两条路线：

- **基础**：模块已注入抖音 → 刷新出会话 → 选中要续的会话 → 套一个模板 → 发出去一次；
- **进阶**：创建标签 → 给会话打标签 → 用搜索找会话 → 不同会话用不同模板 → 把文档导出 / 分享给 AI →
  创建自定义模板 → 创建宏 → 把宏挂到模板或会话。

步骤**必须按顺序完成**：前一步没完成时，后面的步骤显示「完成上一步后解锁」且不能点；基础没走完时点不进进阶。
每一步按真实状态自动打勾，未完成的当前步给出「看说明 / 去刷新 / 去模板」等跳转；**跳到对应页面后，要点的控件会被蓝色描边圈住并持续呼吸，直到你点它才停；同一页有多个目标时一次只圈一个、轮流切换**。内置模板会按行轮流圈（空白模板除外），展开任意一个后只圈「选会话继承」；再展开另一个模板时，框会跟着移到新的那一行上。两条路线全部完成后胶囊自动消失。
**隐藏只在设置里操作**：进入 **设置 → 新手引导**，可以「预览引导」或「隐藏引导」，避免在页面上误触把引导关掉。

### 2.2 模板

- 顶部可**搜索**模板名 / 内容。
- **内置模板**（默认折叠）与**自定义模板**（默认展开）都是折叠分组。
- **点模板标题**展开 / 收起；展开后是该模板的**派生列表**（继承它的会话 / 子模板）和动作：
  - 自定义模板：**编辑模板 / 选会话继承 / 克隆到会话**；
  - 内置模板：**添加为我的模板 / 选会话继承 / 克隆到会话**（内置模板本身不能直接编辑，先复制成自己的）。
- 派生项**点一下**进对应会话（或子模板）的编辑页；**长按**弹「更改模板 / 编辑模板变量」。
- 保存父模板时，如果有的派生模板**改过内容又没开跟随更新**，会先把它们列出来，问你要不要覆盖。

### 2.3 标签

标签用来把会话分组（家人、同事、待续……），是一个**独立的视图维度**：
**不直接改变发送资格**（`autoSend` / `manualSend` / `willSend` 都不看标签），只用于整理、筛选和批量操作；
脚本可以基于会话的 `tags` 自定义逻辑（例如只给「家人」挂某个宏）。

- **建标签**：底部「标签」页 → 新增标签，填名字并选颜色；点一行右侧的编辑图标可以改名 / 换色，删除会把它从所有会话上一起摘掉。
- **标签顺序**：按创建顺序排列（先建的在前）；目前不支持拖动排序，改名 / 换色不会改变位置。
- **标签归属在标签页里管**：点击标签卡片（卡片上写着「点击配置目标」）→ 打开会话选择页，勾选这个标签包含哪些会话（可搜索、可按来源筛，
  确定即替换归属；取消勾选的会话会从这个标签里移除）。
- **单个会话也能选**：进入会话编辑页，顶部「标签」一行直接点标签小药丸开 / 关（不用弹窗，点了就存）。
- **显示与筛选**：会话列表的每一行会显示标签色块；顶部有「标签 / 来源」两排标记。
  标签可以**多选**（选中项背景变蓝，再点取消；命中任一所选标签即显示），来源单选；
  **标签和来源同时选中时是 AND**：两者都要满足才会显示；
  **按标签筛选时，命中的所选标签越多越靠前**，同分保持原顺序。
  行内的标签色块、`继承：X` 那行也可以直接点。搜索框只搜昵称 / 备注。
- **会话选择页**（选会话继承 / 克隆到会话）同样支持：按昵称 / 备注搜索，
  「标签」条可多选、「来源」条按继承自哪个模板（含空白 / 未写）筛，多选后点「确定」。


### 2.4 宏/函数

- 顶部可**搜索**宏 / 函数名与内容。
- 内分「宏 / 函数」两页，列表是卡片列表（不再折叠）；**点一行**编辑，底部按钮新增。

### 2.5 设置

- **总开关**、**刷新会话**、**使用文档**（文档页里可**复制全文** / 导出 `.md` / 分享）。
- 「更多」里的二级页面：**概览 / 手动归属 / 宿主状态 / 配置 / 关于**（顶部返回图标回上一级）。
  - 概览：会话总数、待发、待对方回复、待重燃、今日已续、已选目标、快照时间、今日已发；
  - 手动归属：手动移入 / 移出的数量，可一键清除手动标记；
  - 宿主状态：抖音进程最近一次运行的简报（扫描、发送、失败原因），排查问题先看这里；
  - 配置：导出 / 导入（逐项勾选，导入是合并）。可分别勾选 **模板 / 会话文案 / 宏 / 函数 / 标签**，
    快照与今日已发记录是整类开关；会话列表可搜索、可按单聊 / 群聊筛；
    **勾了会话会自动带上它身上的标签**（导出 / 导入页里这些标签会显示颜色、勾上并置灰，不能取消），导入后标签归属不会丢。
    标签行 / 模板行右侧的 **「一键选中」** 可以一键勾选该标签下或继承该模板的全部会话。
- **新手引导**：预览浮层、隐藏引导；隐藏后也在这里重新打开。

## 三、什么时候会发

**触发时机**

- **打开抖音**：启动约 **5 秒**后开始探测，IM 没就绪就每 **2.5 秒**重试，最多约 **1 分钟**；就绪后写快照并发一轮。
- **回到抖音界面**：刷新一次快照（1 分钟内不重复），当天还没自动跑过就补跑一轮。
- **跨天值守**：23:30 之后每分钟检查一次，23:58–00:05 每 5 秒；抖音开着跨到第二天会自动补一轮。
- **手动发送**：立即发一轮，**不受总开关和「今日已发」限制**。

**发什么、发给谁**

- 发送对象 = **已选目标** = 抖音判定「今天还没互动」的会话（待发 / 待对方回复 / 待重燃），
  手动归属（移入 / 移出）优先于抖音判定。
- **每天每个会话只发一次**；发送成功会记下日期（配置里的 `sentDays`）。
- **待发 vs 待对方回复**：今天还没发的叫「待发」；我们已经发了、火花还是灰的叫「待对方回复」
  （抖音仍算「今天没互动」，但今天不会重复发）。概览页两个数字分开算。
- **群聊默认不发**：群聊单独一张卡片，只有你把它**手动移进已选目标**，或勾选后点「发送给选中的」才会发。
- **没有文案的会话不发**：会话既没有模板正文、也没有挂宏时跳过。
- 抖音启动、跨天补跑、手动刷新之后，**快照会自动写回模块 App**（不用打开 App 也能看到最新数据）。

## 四、模板、变量与保留

### 4.1 模板与继承

- **空白模板不是「不发」**：它就是一个内容为空的普通模板——会话跟随它、出现在它的派生列表里，
  只是没有模板正文，所以发的是会话自己写的那段。内置文案不会自动套用。
- **内置模板**（只是可选起点）：空白模板 / 续火花 / [续火花吧] / 按时问候 / 火花天数打卡 / 简短提醒。
  其中「续火花」固定发一句「续火花」，「[续火花吧]」固定发抖音的续火花表情包。
  点开可以 `添加为我的模板`（复制成可编辑的模板）、`选会话继承`、`克隆到会话`。
- **继承 vs 克隆**：
  - **选会话继承** = 跟随该模板，父模板改了可以同步过来（编辑页勾「自动同步」就是自动跟随）；
  - **克隆到会话** = 只把当前内容复制过去，之后**跟随空白模板**（也算继承自空白）。
  - 两个入口都会打开**会话选择页**：可按昵称 / 备注搜索，按标签（可多选）或来源筛选，多选后点「确定」；
    取消勾选的会话会退回空白模板（自己写），已写内容保留。
- **改某个会话的来源**：点会话行 → 「继承来源」右边的 **更改** → 二级页面按分类挑
  （空白模板 / 内置模板 / 自定义模板 / 内容固定的会话模板）。
  从别的模板切到空白模板时，**已写的文案会保留**。
- **派生自派生**（例如 A → B，C 想用 B 的文案）：C **挂在 A 上**（以后跟 A 同步），**内容复制 B 的当前内容**。

### 4.2 变量（两层）

变量分两层：**模板层**一套，每个**会话**还可以有自己的一套。脚本里统一用 `ctx.template.vars["名字"]` 取值（中文名不能用点号访问）。

- **入口**：
  - 模板的变量：模板编辑页的「变量」；
  - 会话的变量：模板页**长按派生项**选「编辑模板变量」，或会话编辑页的「变量」按钮。
- **两张卡片**：「继承」是父模板定义的（会话页才有），「自定义」是本层新增的。
- **一行一个变量**：左边名字，右边 JS 表达式（小编辑器，带 `ctx.` 与其它变量的补全）。
- **继承项可以改、不能删**：改表达式 = 在这一层**覆盖**父模板的值（父模板不动），旁边「⟲ 还原」恢复。
- **值是 JS 表达式**（不是固定字符串），能读完整的 `ctx`：
  `ctx.io.days > 100 ? "老朋友" : "朋友"`。
- **按上下顺序求值**：下面的表达式可以引用上面已经算出来的变量。
- **会话的变量排在父模板之后**：同名时以会话的为准；**空表达式 = 没填**，回落到父模板，再没有就是 `null`。
- **出错不中断**：某条表达式报错只让那个变量是 `null`，脚本照常执行。
- **「试算」**（标题栏）：按当前会话快照把生效的整套变量跑一遍，列出「名字 = 值」，只算不发。
- **变量名建议用字母 / 数字 / 下划线**：不是合法标识符（带空格或中文）时仍能保存，
  但脚本里只能写成 `ctx.template.vars["名字"]`，也补全不出来。
- 保存时**空名字的行忽略、重名的只留最后一行**；变量随模板 / 会话一起导出 / 导入。

### 4.3 保留策略

- **会话模板与发送记录**：移出「已选目标」后，从移出那天起保留 **30 天**，到期清理；
  从没被选中过的立即清理。
- **会话快照**：连续 **3 次**扫描都没在抖音出现 → 从列表里隐藏；连续 **30 天**没出现 →
  连快照一起删除（手动归属一起清掉）。中途出现一次就重新计数、恢复显示。
- **「被隐藏」卡片**（续火花页底部，默认收起）：
  - 每行显示名字、是否手动移入、最后出现时间、连续未出现次数；
  - **恢复**：把计数清零，立刻回到列表（下次扫描还没出现会再隐藏）；
  - **移出目标**（仅手动移入的显示）：从已选目标移除，仍留在被隐藏列表；
  - **点整行**：进该会话的文案编辑页。

## 五、宏与函数

### 5.1 宏

**宏 = 在模板脚本之后执行的独立小脚本**，适合节日倒计时这类**临时代码**：用完把宏删掉，模板一个字不动。

- 一个宏可以挂到**多个模板或具体会话**，一个模板也可以挂多个宏。
- 执行顺序：`自定义函数注入 → 模板脚本 → 宏（按顺序）`，所以宏可以改写模板已经算好的文案：

```js
// 宏里直接 push 就行：执行宏之前引擎已经保证 ctx.result 是列表
ctx.result.push("（元旦还有 " + ctx.builtin.countdown("2027-01-01") + " 天）");
```

- **动态挂载**：脚本里可以按宏 id 挂载 / 摘掉（下一轮生效，预览时跳过）：

```js
ctx.system.mountMacro("宏 id", { conversation: "会话 id" });
ctx.system.mountMacro("宏 id", { template: "模板 id" });              // 跟着派生会话一起跑
ctx.system.mountMacro("宏 id", { template: "模板 id", inherit: false }); // 仅模板，不往派生会话传播
ctx.system.unmountMacro("宏 id", { conversation: "会话 id" });
ctx.system.unmountAll();                                              // 摘掉当前会话上的所有宏
```

- **宏自己的变量**：`ctx.macro.getvar / setvar / deletevar`，值按 JSON 存进配置、跨次保留，
  归属就是宏自己（另一个宏读不到）；**只有在宏脚本里能读写**，模板段调用会报错。
- 宏编辑页的「沙盒变量」一行点进去，可以改名 / 改 JSON 值 / 删除 / 新增（单独一页，不和脚本编辑器挤在一起）；
  删掉宏时它名下的变量一起清掉。

### 5.2 自定义函数

在 **宏/函数 → 函数** 页里**直接写完整函数声明**（只允许一个函数），保存时自动解析出函数名与形参，
注入成 `ctx.functions.<名字>`：

```js
// 函数页里就写这一段（原样，不要只写函数内部）
function daysTo(date) {
  var target = new Date(date + "T00:00:00");
  return Math.ceil((target - new Date()) / 86400000);
}
```

```js
// 定义好之后，模板 / 宏里这样调用
ctx.result.push(ctx.io.name + "，距离元旦还有 " + ctx.functions.daysTo("2027-01-01") + " 天");
```

- **只能有一个函数**：声明之后再写第二个函数或别的语句，保存时会报错并指出位置；
- 名字与形参由声明决定，不用另外填；说明（可选）会出现在编辑器的补全提示里；
- 早期版本只存了「函数内部」，打开会自动补成完整声明，可以继续编辑。

## 六、脚本 API

脚本是一段 JavaScript（Rhino 沙盒：**没有** Java / DOM / 网络 / 文件 / 定时器，单次执行 **2 秒**上限）。

### 6.1 输出：`ctx.result`

- 引擎在脚本执行前把它初始化成**空列表** `[]`，用 `ctx.result.push("每行内容")` 逐行添加；
- **按行拼接成一条消息**；**空列表 = 这条不发**；
- 也可以直接赋值：`ctx.result = "早安"`（当成一行），但推荐只用 push（类型是 `string[]`）；
- 每个宏执行前，引擎会把两处引用同步一次，所以宏里放心 `.push()`。

```js
var 谁 = ctx.io.name || "朋友";
ctx.result.push("早安，" + 谁 + "！第 " + ctx.io.days + " 天的火花，别忘了续上 🔥");
```

### 6.2 变量

**`ctx.builtin` —— 引擎自己算的**

### 6.3 系统接口与会话筛选

| 调用 | 说明 |
| --- | --- |
| `ctx.system.getAllConversation(filter?)` | 本轮可见的会话数组，可按条件筛（见下） |
| `ctx.system.getConversation(id)` | 按会话 id 取详细信息，没有返回 `null` |
| `ctx.system.getTemplate(id)` | 按模板 id 取：`{ id, name, body, childs, isBuiltin }` |
| `ctx.system.getMacro(id)` | 按宏 id 取：`{ id, name, body, templates, conversations }` |
| `ctx.system.mountMacro(id, target?)` | 按宏 **id** 挂到指定目标（不传 = 当前会话） |
| `ctx.system.unmountMacro(id, target?)` | 按宏 **id** 从指定目标摘掉 |
| `ctx.system.unmountAll(target?)` | 把指定目标上的所有宏都摘掉 |

`target` 用对象传：`{ conversation: "会话 id" }` 或 `{ template: "模板 id", inherit: false }`。

会话筛选里的 `tags` 用**特殊写法**（不是普通字段相等）：`{ tags: { include: [...], except: [...] } }`，
内层数组是交集（都要有）、外层数组是并集（任一组成立即可），元素可以写标签 id 或名字；详见下面「按标签筛选」。

**会话字段**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 会话 id（与 `ctx.io.id` 一致） |
| `nickname` | string | 昵称（原始昵称） |
| `name` | string | 显示名（备注优先，其次昵称） |
| `remark` | string | 备注名（可能为空） |
| `peerUid` | string | 对方 UID |
| `tags` | `Array<{ id, name }>` | 这个会话的标签列表（可以是空数组） |
| `days` | number | 已连续聊天天数 |
| `state` / `stateText` | number / string | 火花状态码与文本 |
| `isGroup` | boolean | 是否群聊 |
| `selected` | boolean | 是否在「已选目标」里（已隐藏的会话不算） |
| `sentToday` | boolean | 今天是否已经发过 |
| `manualSend` | boolean | **手动**发送会不会发它（点名时只看点名，否则按候选） |
| `autoSend` | boolean | **自动**发送会不会发它（按抖音判定 / 手动归属，且今天还没发） |
| `willSend` | boolean | **本轮实际**会不会发（自动轮按自动口径，手动轮按手动口径） |

`getConversation(id)` 额外带 `template` / `parent` / `macros` 三块。

**筛选**：参数可以是对象，也可以是函数；返回类型都是 `SparkConversation[]`（新数组，不改原列表）。

对象里能用的键（就是会话字段；值的写法见下表）：

| 键 | 类型 | 示例 |
| --- | --- | --- |
| `id` | string | `{ id: "0:1:1097767269175691:2551343785182968" }` |
| `nickname` | string | `{ nickname: "小明" }` |
| `name` | string | `{ name: "小明" }`（显示名，备注优先） |
| `remark` | string | `{ remark: "同事" }` |
| `peerUid` | string | `{ peerUid: "123456" }` |
| `days` | number | `{ days: 100 }` 或 `{ days: function (d) { return d >= 100; } }` |
| `state` | number | `{ state: [1, 2] }`（1 已互动 / 2 待互动 / 3 待重燃） |
| `stateText` | string | `{ stateText: "待重燃" }` |
| `isGroup` | boolean | `{ isGroup: false }` |
| `selected` | boolean | `{ selected: true }` |
| `sentToday` | boolean | `{ sentToday: false }` |
| `manualSend` | boolean | `{ manualSend: true }` |
| `autoSend` | boolean | `{ autoSend: true }` |
| `willSend` | boolean | `{ willSend: true }` |
| `tags` | 对象 / 数组 | 见下（标签的两级条件） |

每个字段的值都可以写成三种形式：

| 值 | 含义 |
| --- | --- |
| 字符串 / 数字 / 布尔 | 字段必须等于这个值 |
| 数组 | 字段等于其中任意一个 |
| 函数 | `(字段值) => boolean`，自定义判断 |

标签条件写在 `tags` 里（元素可以是标签 id，也可以是标签名）：

```js
{
  tags: {
    include: [[...], [...]],  // 内层数组 = 交集（组内标签都要有）；外层数组 = 并集（任一组成立即可）
    except: [[...], [...]]    // 命中的会话被排除，语义同 include
  }
}
```

| 写法 | 含义 |
| --- | --- |
| `tags: [["家人", "同事"]]` | 同时有「家人」和「同事」 |
| `tags: [["家人"], ["同学"]]` | 有「家人」**或**有「同学」 |
| `tags: ["家人"]` | 一维数组 = 单个交集组，等同 `[["家人"]]` |
| `tags: { except: [["同事"]] }` | 排除有「同事」的会话 |

```js
// 字段筛选
var targets = ctx.system.getAllConversation({ willSend: true });
var singles = ctx.system.getAllConversation({ isGroup: false, selected: true });
var hot = ctx.system.getAllConversation({ state: [1, 2] });
var longSpark = ctx.system.getAllConversation({ days: function (d) { return d >= 100; } });

// 标签：同时有「家人」和「同事」，或者有「同学」
var tagged = ctx.system.getAllConversation({ tags: { include: [["家人", "同事"], ["同学"]] } });
// 排除有「同事」或同时有「家人」「同学」的会话
var filtered = ctx.system.getAllConversation({ tags: { except: [["同事"], ["家人", "同学"]] } });

// 函数：逐项判断
var need = ctx.system.getAllConversation(function (c) { return c.autoSend && c.days > 30; });
```

**`getConversation(id)` 的完整用法**

传入会话 id，返回**一个**会话详情对象（就是 `getAllConversation()` 数组里的元素，再加下面三块）；找不到返回 `null`：

```js
var c = ctx.system.getConversation("0:1:1097767269175691:2551343785182968");

if (c) {
  // 基础字段（与 getAllConversation 的元素完全一致）
  c.id;          // 会话 id（string）
  c.nickname;    // 昵称（string）
  c.name;        // 显示名：备注优先，其次昵称（string）
  c.remark;      // 备注名，可能为空（string）
  c.peerUid;     // 对方 UID（string）
  c.tags;        // 标签列表：[{ id, name }]
  c.days;        // 已连续聊天天数（number）
  c.state;       // 火花状态码：1 今天已互动 / 2 今天还没互动 / 3 待重燃（number）
  c.stateText;   // 火花状态文本（string）
  c.isGroup;     // 是否群聊（boolean）
  c.selected;    // 是否在「已选目标」（boolean）
  c.sentToday;   // 今天是否已发（boolean）
  c.manualSend;  // 手动发送会不会发它（boolean）
  c.autoSend;    // 自动发送会不会发它（boolean）
  c.willSend;    // 本轮实际会不会发（boolean）

  // 详情额外字段（getAllConversation 没有）
  c.template;    // 这个会话自己的模板：{ id, name, body }
  c.parent;      // 继承来源：{ id, name, body }
  c.macros;      // 挂在这个会话上的宏：[{ id, name }]
}
```

| 详情字段 | 类型 | 说明 |
| --- | --- | --- |
| `template` | `{ id, name, body }` | 这个会话自己的模板（空白模板时 `body` 为空串） |
| `parent` | `{ id, name, body }` | 继承来源（`id` 可能是内置模板 id，如 `builtin:blank`） |
| `macros` | `Array<{ id, name }>` | 挂在会话或父模板上的宏 |

### 6.4 发送结果回调：`ctx.registerCallback`

脚本可以注册一个回调，宿主在**这个会话处理结束**后调用它：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 刚处理完的会话 id |
| `result` | string | `"Succeed"` 发送成功 / `"Skipped"` 跳过 / `"Failed"` 发送失败 |
| `reason` | string? | 具体原因（跳过 / 失败时一般会有，成功时不带） |

**下面这段要写在宏里**（模板 / 会话文案段没有写权限，`ctx.macro.setvar` 会失败）。

```js
ctx.registerCallback(function (res) {
  if (res.result === "Succeed") {
    ctx.macro.setvar("lastSent", res.id);
  } else if (res.result === "Skipped") {
    ctx.macro.setvar("lastSkip", res.reason || "");   // 例如：脚本没有产出内容
  } else {
    ctx.macro.setvar("lastError", res.reason || "");  // Failed：失败原因
  }
});
```

- 每个会话的脚本各自注册、各自回调；回调里改的沙盒变量 / 宏挂载会和这一轮的其他改动一起落盘。
  回调里要用 `ctx.macro` 的话，**注册它的脚本本身得是宏**（模板段没有写权限）。
- 只有**脚本跑过**的会话才会回调：`Succeed`（发送成功）、`Failed`（发送失败）、
  `Skipped`（脚本跑完但 `ctx.result` 是空的，这一条不发）。
- 「今日已发」「没写文案」这类**在脚本执行前就筛掉**的会话不会回调（脚本没跑，也就没有回调）。
- 预览 / 试算不注册回调。

### 6.5 宏自己的变量：`ctx.macro`

| 调用 | 说明 |
| --- | --- |
| `ctx.macro.id` / `ctx.macro.name` | 当前宏的 id / 名字（模板段为空串） |
| `ctx.macro.getvar(name)` | 读一个键；没有就是 `undefined` |
| `ctx.macro.setvar(name, value)` | 写一个键；值可以是对象 / 数组 / 数字 / 字符串，存成 JSON |
| `ctx.macro.deletevar(name)` | 删一个键（只能删自己创建的） |

```js
// 宏里：记录这个宏跑过几次
var n = (ctx.macro.getvar("runs") || 0) + 1;
ctx.macro.setvar("runs", n);
ctx.result.push("（第 " + n + " 次加这句）");
```

### 8.2 写作建议

1. **正文只写正文**：`称呼`、`语气` 这类「人设」放变量，模板只负责把句子说出来——换人设只改变量。
2. **多准备池子**：问候语、话题、表情用数组 + `ctx.builtin.pick()` 抽，避免每天一模一样。
3. **临时代码用宏**：节日倒计时、一次性祝福放宏里，用完删掉，模板一个字不动。
4. **能算的别写死**：天数用 `ctx.io.days`、日期用 `ctx.builtin.date` / `formatDate`、倒计时用 `ctx.builtin.countdown`。
5. **兜底**：`ctx.io.days` 可能是 0、`ctx.io.remark` 可能为空、变量可能是 `null` —— 用 `||` 或三元给默认值。
6. **控制在 1~2 行**：多行会被拼成一条消息，太长不像真人。
7. **别重复系统能力**：每天只发一次、跳过已发的会话，系统已经做了。

- [ ] 只用 `ctx.*` 和 `Math / JSON / Date / Array / String`，没有网络 / DOM
- [ ] push 的最终都是字符串（数字先 `String(x)` 或 `+ ""`）
- [ ] `ctx.io.name`、`ctx.io.days`、变量都有兜底（不会输出 `undefined` / `null`）
- [ ] 不会超过 2 秒（没有大循环）
- [ ] 至少有一条路径会 push（否则这条永远不发）
- [ ] 变量表达式只引用排在它前面的变量

## 九、常见问题

**Q：列表里全是「无名」？**
A：抖音还没把会话数据准备好。到设置页点「刷新会话」，或重启抖音后等几秒再刷新。

**Q：点了抖音设置页的「续火花」没反应？**
A：抖音会拦截外部跳转并弹确认框，**3 秒内点「继续」**才会打开；也可以用桌面图标进。

**Q：设置页「宿主状态」一直空着？**
A：说明模块没被注入抖音——检查 LSPosed 里模块是否启用、作用域是否勾了「抖音」，然后重启抖音。

**Q：为什么有的会话不发？**
A：常见原因：① 它还没写文案（没模板正文、也没挂宏）；② 抖音判定今天已经互动过；
③ **自动发送**的总开关没开（手动发送不受这个开关影响）；④ 是群聊且没手动移进已选目标。

**Q：什么时候会扫描？**
A：抖音冷启动、回到前台、跨天、手动刷新/发送时各扫一轮（回前台有 10 秒限流，自动任务刚跑完 60 秒内不重复）。
界面内切换页面只刷新快照，不重复扫描。

**Q：覆盖安装后第一次打开抖音没有自动发？**
A：`adb install` 覆盖安装 / 强制停止会把模块 App 置为「停用」，广播和 provider 都会被系统丢掉。
先打开一次模块 App（桌面图标），再回抖音即可；之后不会再弹「是否跳转」。

**Q：会话突然不见了？**
A：它被「隐藏」了：连续 3 次扫描没在抖音出现就会收进续火花页底部的「被隐藏」卡片，
可以点「恢复」把它放回来；满 30 天没出现才会连快照一起删。

**Q：头像 / 备注不更新？**
A：头像与备注来自抖音的会话数据，重启抖音后点「刷新会话」即可刷新。

## 十、数据与文件位置

- 配置与快照：`/data/data/io.github.worldmargin.sparkflame/files/spark_config.json`（单文件，跨进程共享）。
- 发送记录：配置里的 `sentDays`（每个会话记录最后一次发送日期，每天只发一次）。
- 「今天是否已自动跑过」：抖音自己目录下的 `spark_last_auto_day`（跟着抖音的数据走）。
- 卸载模块 App 会一并清掉配置（抖音里的登录态不受影响）。

## 附录：一次发送的完整时序

```
抖音启动 / 回到前台 / 跨天值守 / 手动发送
  └─ 扫会话（宿主 IM）→ 生成快照：昵称、备注、天数、火花状态、会话 ID、是否群聊
      └─ 对每个候选会话：挑模板（会话自己的 > 继承的父模板）
          ├─ 合并变量：父模板变量 → 会话变量（同名覆盖、空值回落、都没有 = null）
          ├─ 注入自定义函数：ctx.functions.<名字>
          ├─ 执行模板脚本（Rhino 沙盒，2 秒上限）
          ├─ 依次执行挂上的宏（每次执行前同步结果列表）
          └─ ctx.result（字符串列表）→ 逐行拼接成一条消息
              └─ 空列表 = 这条不发；今天已发过 = 跳过；没有文案 = 跳过
                  └─ 发送成功后记下日期，并把 Succeed / Skipped / Failed 回调给脚本注册的函数
```
