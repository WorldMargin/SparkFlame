# 给 AI 的模块说明书

> 这份文档写给「要替这个模块写模板脚本的 AI」看，也写给想弄清它到底怎么工作的人看。
> 面向人的操作说明在 [`manual.md`](manual.md)（同 `使用文档.md`）；这里只讲**机制、契约和怎么写才贴合设计**。

## 1. 一句话

LSPosed 模块注入抖音进程，按你配置的**模板 / 变量 / 宏 / 函数**跑一段 JavaScript，把结果拼成一条私信，
在「抖音判定今天还没互动」的会话里自动发出去 —— 每天每个会话最多一条。

## 2. 一次发送的完整时序

```
抖音启动 / 跨天值守 / 手动点「发送」
  └─ 扫会话（宿主 IM）→ 生成快照：昵称、备注、天数、火花状态、会话 ID、是否群聊
      └─ 对每个会话：挑模板（会话自己的 > 继承的父模板）
          ├─ 组装变量：父模板变量 → 会话变量（同名覆盖、空值回落、都没有 = null）
          ├─ 注入自定义函数：ctx.functions.<名字>
          ├─ 执行模板脚本（Rhino 沙盒，2 秒上限）
          ├─ 依次执行挂上的宏（结果变量每次执行前都归一成列表）
          └─ $spark_result$（字符串列表）→ 逐行拼接成一条消息
              └─ 空列表 = 这条不发；已发过（当天）= 跳过；没写文案 = 跳过
                  └─ 发送成功后记录 sentDays[会话] = 今天
```

要点：

- **模板脚本只负责产出文案**。昵称、称呼、语气这些"人设"放在变量里，不要写死在模板里 —— 这样换人设只改变量。
- **一条消息 ≠ 多条**：`$spark_result$` 里的多行会被拼成**一条**消息（用换行分隔），不是发多条。
- **每天每会话只发一次**：发过就记进 `sentDays`，当天不再发；手动发送可以强制再发一次。
- 变量、宏、函数都是**在发送前组装**的，不参与网络请求，也不缓存上次结果。

## 3. 数据模型（和脚本有关的那些）

| 概念 | 说明 | 脚本里怎么用 |
| --- | --- | --- |
| 一级模板 | 一段 JS（`$spark_result$` 列表），可被多个会话继承 | 直接就是脚本 |
| 派生模板（会话模板） | 会话自己的模板，可继承某个一级模板，也可克隆成独立的一份 | 继承时"跟随父模板"，改父模板它跟着变；克隆是复制一份，之后各改各的 |
| 空白模板 | 内容为空的模板；**等价于"不用模板、自己写"**，照常发送 | 脚本就是空的，什么都不产出 → 不发（见 §5） |
| 模板变量 | 一级模板层的变量，`名字 → JS 表达式` | `ctx.template.名字` |
| 会话变量 | 会话层的变量，覆盖同名模板变量 | 同上（自动合并，脚本无需区分） |
| 宏 | 挂在模板或会话上的小脚本，模板之后执行，按挂载顺序 | 直接 `$spark_result$.push(...)` |
| 函数 | 全局函数声明（只允许一个函数），注入成 `ctx.functions.<名>` | `ctx.functions.名字(实参)` |
| 快照 | 发送时的会话数据 | 即 `ctx.*` 字段 |

变量求值顺序：**父模板的变量按声明顺序 → 会话的变量按声明顺序**，后面的可以引用前面的
（`ctx.template.已算出的名字`）。同名时后者覆盖前者。

## 4. 契约（写错这里最容易"发了但内容不对"）

- **输出**：`$spark_result$` 是一个**字符串列表**，引擎执行前会初始化为 `[]`。
  - 写：`$spark_result$.push("...")`（推荐）；`$spark_result$ = "..."` 也兼容（会被当成一行）。
  - **空列表 = 不发这条**。模板什么都没 push，就等价于"这次不发"。
- **语言与限制**：Rhino 沙盒（引擎 1.7.15），**没有** Java / DOM / 网络 / 文件 / 定时器；**单次 2 秒超时**，
  超时按失败处理。内置模板统一用 ES5 写法（`var` + 字符串拼接），照这个风格写最稳。
- **可用的东西**：`ctx`（下表）、`Math`、`JSON`、`Date`、`Array` / `String` 的常规方法、`parseInt / parseFloat / isNaN`。
- **别做的事**：不要写 `while(true)`、不要递归几千层、不要假设有 `fetch` / `require` / `localStorage`。
- **容错**：变量表达式报错只会让那个变量是 `null`，不会中断；**模板脚本本身报错 = 这条发送失败**（会在界面/简报里看到失败）。

## 5. 什么时候会发、什么时候不发

会发：会话被判定"今天还没互动"（`ctx.state === 2` 或 `3`），且（有模板 或 手动选中），且今天没发过。

不发：

1. 模板脚本产出空列表（最常见：空白模板但没写内容）；
2. 今天已经发过（`sentDays` 有今天）—— 手动发送可以忽略这条；
3. 总开关关闭（自动触发时）；未登录；会话列表没取到；
4. 群聊默认不参与自动发送（手动移进「已选目标」才发）。

## 6. API 参考

### 6.1 `ctx`（当前会话）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ctx.date` | string | 当天日期 `yyyy-MM-dd` |
| `ctx.time` | string | 当前时间 `HH:mm` |
| `ctx.weekday` | string | 星期几 |
| `ctx.timestamp` | number | 当前毫秒时间戳 |
| `ctx.nickname` | string | 对方昵称 |
| `ctx.remark` | string | 备注名（可能为空） |
| `ctx.name` | string | 显示名（备注优先，其次昵称） |
| `ctx.days` | number | 已连续聊天天数（没有火花时通常是 0） |
| `ctx.state` | number | 1 今天已互动 / 2 今天还没互动 / 3 待重燃 |
| `ctx.stateText` | string | 火花状态文本（"可点亮" 之类） |
| `ctx.peerUid` | string | 对方 UID |
| `ctx.conversationId` | string | 会话 ID |
| `ctx.template.名字` | any | 变量（两层合并后的值；算不出来是 `null`） |

### 6.2 内置函数

| 调用 | 返回 | 说明 |
| --- | --- | --- |
| `ctx.pick(list)` | any | 随机取一个 |
| `ctx.pad(n)` | string | 补零到两位 |
| `ctx.repeat(s, n)` | string | 重复字符串 |
| `ctx.random(a, b)` | number | `[a, b)` 随机整数 |
| `ctx.shuffle(list)` | any[] | 洗牌（新数组） |
| `ctx.countdown(target)` | number | 距目标日期天数（已过为负） |
| `ctx.nextNewYear()` | string | 下一个元旦日期 |
| `ctx.untilNewYear()` | number | 距下一个元旦天数 |
| `ctx.formatDate(date, pattern)` | string | 按 `yyyy/MM/dd/HH/mm/ss` 格式化 |
| `ctx.functions.名字(...)` | any | 自定义函数 |

## 7. 怎么写才"贴合设计"

1. **正文只写正文**：不要在模板里拼"`ctx.name` + '，'" 这类前缀 —— 称呼属于变量（`ctx.template.称呼`），
   语气属于变量（`ctx.template.语气`），模板只负责把句子说出来。
2. **多准备池子**：问候语、话题、表情用数组 + `ctx.pick()` 抽，避免每天一模一样。
3. **临时代码用宏**：节日倒计时、一次性活动祝福放宏里，用完删掉，模板完全不动。
4. **能算的别写死**：天数用 `ctx.days`、日期用 `ctx.date` / `ctx.formatDate`、倒计时用 `ctx.countdown`。
5. **兜底**：`ctx.days` 可能是 0、`ctx.remark` 可能为空、变量可能是 `null` —— 用 `||` 或三元给默认值。
6. **控制在 1~2 行**：拼成一条消息，太长不像真人。
7. **别重复系统能力**：已经在"每天只发一次"上做了去重，脚本里不用再判断今天发没发。

## 8. 写完自检（照这个清单过一遍）

- [ ] 语法是 ES5（`var`、字符串拼接），没有箭头函数/模板字符串依赖
- [ ] 只用 `ctx.*`、`Math / JSON / Date / Array / String` 这些，没有网络/DOM
- [ ] 所有 push 的最终都是字符串（数字先 `String(x)` 或 `+ ""`）
- [ ] `ctx.name`、`ctx.days`、变量都有兜底（不会输出 `undefined` / `null`）
- [ ] 不会超过 2 秒（没有大循环）
- [ ] 至少一条路径会 push（否则这条永远不发）
- [ ] 变量里的表达式不引用"还没算出来"的变量（只能引用排在前面的）

## 9. 例子：变量 + 模板 + 宏

**变量（模板层）**

| 名字 | 表达式 |
| --- | --- |
| `称呼` | `ctx.nickname.slice(0, 2)` |
| `语气` | `ctx.days > 100 ? "老朋友" : "朋友"` |
| `尾巴` | `ctx.pick(["✨", "🔥", "🌙"])` |

**模板**

```js
var hour = parseInt(ctx.time.split(":")[0], 10);
var hello =
  hour < 5 ? "夜深了" :
  hour < 11 ? "早" :
  hour < 13 ? "中午好" :
  hour < 18 ? "下午好" : "晚上好";

$spark_result$.push(ctx.template.称呼 + "，" + hello + "，今天也要好好吃饭" + ctx.template.尾巴);
$spark_result$.push(ctx.template.语气 + "，火花 " + ctx.days + " 天啦，别断");
```

**宏（节日用，之后可删）**

```js
$spark_result$.push("（元旦还有 " + ctx.countdown("2027-01-01") + " 天）");
```

期望输出（一行消息里的两行）：

```
阿泽，晚上好，今天也要好好吃饭🔥
老朋友，火花 493 天啦，别断
（元旦还有 76 天）
```

## 10. 给 AI 的提示词（可以直接贴）

```
你在帮我写一个抖音自动续火花模块的模板脚本（JavaScript，Rhino 沙盒，2 秒上限，无网络/DOM/Java）。
模块工作方式：每次发送时，先合并两层变量（父模板 → 会话，同名覆盖、空值回落、都没有为 null），
再注入自定义函数 ctx.functions.*，然后执行模板脚本，最后执行挂载的宏；
脚本通过 $spark_result$.push("...") 逐行添加内容，多行会被拼成一条消息，空列表表示这条不发。
可用对象：ctx.date/time/weekday/timestamp/nickname/remark/name/days/state/stateText/peerUid/conversationId，
ctx.template.<变量名>，以及 ctx.pick/pad/repeat/random/shuffle/countdown/nextNewYear/untilNewYear/formatDate。
限制：只能用 var 与字符串拼接（ES5），只能用 Math/JSON/Date/Array/String 常规方法，不能有死循环。
要求：1~2 行、口语化、每天有变化（用 ctx.pick）、对 ctx.days 与变量做兜底、不写死昵称。
请先告诉我你打算放哪些变量（名字 + 表达式），再给出模板脚本与（可选的）宏脚本。
```
